## Where we are

From A1 you know how Java runs: `javac` to bytecode, then the JVM interprets and JIT-compiles it.
Both the language and the JVM keep changing. Interviewers routinely ask "what changed since Java
8?" and expect *why*, not a list. This lesson walks the long-term-support releases 8 → 11 → 17 →
21 → 25, showing for each feature the pain it removed, with before/after code.

## The problem

Many codebases (and many engineers' habits) are still shaped by Java 8. Code written that way
compiles fine on Java 21, but it is longer, more error-prone, and misses whole capabilities, such
as a million concurrent blocking tasks. To read modern code, review it and talk about it in
interviews, you need the map.

## How Java is released

- Since Java 10 (March 2018), a new version ships **every six months** (March and September).
- Every so often one is a **long-term support (LTS)** release that vendors patch for years: 8
  (2014), 11 (2018), 17 (2021), 21 (2023), 25 (2025). Most companies jump from LTS to LTS.
- A **preview feature** is complete but not final; it may change or be removed. It only compiles
  with `--enable-preview`. An **incubator** module is earlier still. Never present a preview
  feature as standard Java.

The cautionary tale: *string templates* were a preview in Java 21 and 22, then **withdrawn** in 23.
Previews really can disappear.

## Java 8 (2014): functions as values

**Problem:** passing behaviour required anonymous classes, so collection processing was long
loops with mutable accumulators.

```java
// Before (Java 7)
List<String> names = new ArrayList<>();
for (Employee e : employees) {
    if (e.salary() > 100_000) {
        names.add(e.name().toUpperCase());
    }
}
Collections.sort(names);

// After (Java 8): lambdas + streams
List<String> names = employees.stream()
        .filter(e -> e.salary() > 100_000)
        .map(e -> e.name().toUpperCase())
        .sorted()
        .collect(Collectors.toList());
```

- **Lambdas** and **method references** (`System.out::println`): a short way to pass behaviour.
- **Streams**: declarative pipelines over collections.
- **Default methods** in interfaces. *Why they were needed:* adding `stream()` to `Collection`
  would otherwise have broken every class implementing it.
- **`Optional`**: a return type that says "may be empty", instead of surprise `null`.
- **`java.time`** (`LocalDate`, `Instant`, `Duration`) replaced the mutable, confusing
  `Date`/`Calendar`.
- **`CompletableFuture`** for composing async work (B5).
- Under the hood: **metaspace replaced PermGen** (A2), and `HashMap` buckets with many collisions
  turn into balanced trees, so worst-case lookup is O(log n), not O(n).

## Java 9–11 (2017–2018): modules, less ceremony, a real HTTP client

```java
// Before
Map<String, Integer> limits = new HashMap<>();
limits.put("free", 10);
limits.put("pro", 100);
limits = Collections.unmodifiableMap(limits);
HttpURLConnection conn = (HttpURLConnection) new URL(url).openConnection(); // + streams, + close

// After (9, 10, 11)
var limits = Map.of("free", 10, "pro", 100);           // 9: immutable factories; 10: var
var client = HttpClient.newHttpClient();                // 11: java.net.http
var response = client.send(
        HttpRequest.newBuilder(URI.create(url)).build(),
        HttpResponse.BodyHandlers.ofString());
```

- **9: the module system (JPMS).** *Problem:* any library could reach into JDK internals like
  `sun.misc`, which made the JDK impossible to evolve. Modules declare what they export. The JDK
  itself was split into modules.
- **9:** `List.of`/`Set.of`/`Map.of` (immutable; they reject `null`), `jshell`, **G1 becomes the
  default collector**, **compact strings** (Latin-1 text stored as 1 byte per char, roughly
  halving the memory of most strings).
- **10: `var`** for local variables. The type is still static, just inferred.
- **11 (LTS):** standard `HttpClient` (HTTP/2, async), `String.isBlank/strip/lines/repeat`,
  `Files.readString`, running a single source file with `java Hello.java`, **Flight Recorder**
  open-sourced into OpenJDK (A8), ZGC as an experiment.
- **11 also removed** the bundled Java EE and CORBA modules (JAXB, `javax.xml.bind`, JAX-WS). This
  is the classic 8 → 11 migration break: add them back as Maven dependencies.

## Java 12–17 (2019–2021): modelling data

**Problem:** a plain data carrier needed constructor, getters, `equals`, `hashCode`, `toString`:
fifty lines where most bugs come from a forgotten field.

```java
// Before: a "simple" value class
public final class Money {
    private final long cents; private final String currency;
    public Money(long cents, String currency) { this.cents = cents; this.currency = currency; }
    public long cents() { return cents; }
    public String currency() { return currency; }
    @Override public boolean equals(Object o) {
        if (!(o instanceof Money)) return false;
        Money m = (Money) o;
        return cents == m.cents && currency.equals(m.currency);
    }
    @Override public int hashCode() { return Objects.hash(cents, currency); }
    @Override public String toString() { return "Money[" + cents + " " + currency + "]"; }
}

// After (16): a record
public record Money(long cents, String currency) {
    public Money {                                    // compact constructor for validation
        if (cents < 0) throw new IllegalArgumentException("negative");
    }
}
```

```java
// Before
String label;
switch (status) {
    case ACTIVE: label = "on"; break;                 // forget a break: silent fall-through bug
    case SUSPENDED: label = "paused"; break;
    default: label = "off";
}
if (obj instanceof String) { String s = (String) obj; use(s); }
String json = "{\n  \"id\": 1,\n  \"name\": \"Akhil\"\n}";

// After (14, 16, 15)
String label = switch (status) {                     // 14: switch expression, no fall-through
    case ACTIVE -> "on";
    case SUSPENDED -> "paused";
    default -> "off";
};
if (obj instanceof String s) { use(s); }             // 16: pattern matching for instanceof
String json = """
        {
          "id": 1,
          "name": "Akhil"
        }
        """;                                          // 15: text blocks
```

- **14: helpful NullPointerExceptions** name exactly which reference was null
  (`Cannot invoke "Order.total()" because "order" is null`); on by default from 15.
- **15:** ZGC and Shenandoah become production features.
- **16:** `Stream.toList()` (an unmodifiable list).
- **17 (LTS): sealed classes.** *Problem:* you could not say "a `Shape` is *only* a circle, square
  or rectangle", so every `switch` over subtypes needed a defensive `default`. `sealed ...
  permits` closes the hierarchy, which 21 uses for exhaustive switches.
- **17 also strongly encapsulates JDK internals** (reflective access to private JDK fields is
  denied unless you pass `--add-opens`). This is the classic 11 → 17 break for old libraries;
  upgrade the library rather than adding flags.

## Java 21 (2023): virtual threads and data-oriented code

**Problem 1:** each Java thread was an OS thread (around a megabyte of stack, expensive to
create), so thread-per-request servers topped out at a few thousand concurrent requests and
people moved to complex reactive code to scale.

```java
// Before: a bounded pool of OS threads; 10,000 blocking calls queue up behind 200 threads
ExecutorService pool = Executors.newFixedThreadPool(200);

// After: one cheap virtual thread per task
try (var pool = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 10_000; i++) {
        pool.submit(() -> callSlowService());    // blocking is fine: the carrier thread is released
    }
}                                                // close() waits for all tasks
```

**Virtual threads** are scheduled by the JVM onto a few OS "carrier" threads; when one blocks on
I/O, it is unmounted and the carrier runs another. Blocking code scales again (B6 covers pinning
and limits).

**Problem 2:** handling a closed set of types meant `instanceof` chains or the visitor pattern.

```java
sealed interface Shape permits Circle, Square, Rect {}
record Circle(double r) implements Shape {}
record Square(double side) implements Shape {}
record Rect(double w, double h) implements Shape {}

static double area(Shape s) {
    return switch (s) {                          // pattern matching for switch
        case Circle c -> Math.PI * c.r() * c.r();
        case Square(double side) -> side * side; // record pattern: deconstructs the record
        case Rect(double w, double h) -> w * h;
    };                                           // no default: the compiler knows it's exhaustive
}
```

Add a fourth `Shape` and every non-exhaustive switch becomes a **compile error**, not a runtime
surprise.

**Problem 3:** "get the last element" was different for every collection type. **Sequenced
collections** add `getFirst()`, `getLast()`, `reversed()`, `addFirst()` to `List`, `Deque`,
`LinkedHashSet`, `LinkedHashMap` and friends.

Also in 21: **generational ZGC** (opt-in with `-XX:+ZGenerational`, A4). Previews in 21:
structured concurrency, scoped values, unnamed variables, unnamed classes and instance main
methods, string templates.

## Java 22–25 (2024–2025): finishing the story

Finalised between 21 and 25 (non-LTS releases, but all available in 25):

- **22:** unnamed variables and patterns, `_` for things you must name but don't use
  (`catch (NumberFormatException _)`); the **Foreign Function & Memory API** (call native code and
  manage off-heap memory without JNI); launching multi-file source programs.
- **23:** Markdown in Javadoc comments; generational mode becomes ZGC's default.
- **24:** **stream gatherers** (custom intermediate stream operations, e.g.
  `stream.gather(Gatherers.windowFixed(3))`); the class-file API; **virtual threads no longer pin
  their carrier inside `synchronized`**, removing the biggest virtual-thread caveat of 21; ahead-of-
  time class loading and linking (Project Leyden's first step); single-generation ZGC removed.

**Java 25 (LTS, September 2025)**, final features:

```java
// Compact source files and instance main methods: a whole program (needs JDK 25)
void main() {
    IO.println("Hello, " + "Akhil");
}
```

- **Compact source files and instance main methods**: no `class`, no `static`, no `String[]`
  for small programs and teaching. `IO.println` is a new convenience class.
- **Module import declarations**: `import module java.base;` imports every package a module
  exports.
- **Flexible constructor bodies**: statements (like validation) may run *before* `super(...)`, as
  long as they don't touch `this`.

```java
// Before: validation had to happen after super(...) or in a static helper
// After (25)
class PositiveAmount extends Amount {
    PositiveAmount(long cents) {
        if (cents <= 0) throw new IllegalArgumentException("must be positive");
        super(cents);
    }
}
```

- **Scoped values**: a safer, immutable replacement for many `ThreadLocal` uses, designed to work
  well with huge numbers of virtual threads (`ScopedValue.where(USER, user).run(() -> handle())`).
- **Compact object headers** become a product feature, opt-in with
  `-XX:+UseCompactObjectHeaders` (8-byte headers instead of 12; less memory per object).
- **AOT ergonomics and method profiling** (Leyden): easier to create an ahead-of-time cache and
  have a warmed-up profile at start-up, cutting warm-up time (A1).
- Generational Shenandoah becomes a product feature; the 32-bit x86 port is removed.

Still **preview** in 25 (do not call these final): structured concurrency, primitive types in
patterns, stable values. The Vector API is still incubating.

## Lab (~10 min)

Save as `Modern.java`:

```java
import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.Executors;
import java.util.concurrent.atomic.AtomicInteger;

public class Modern {
    sealed interface Shape permits Circle, Square, Rect {}         // 17: sealed
    record Circle(double r) implements Shape {}                     // 16: records
    record Square(double side) implements Shape {}
    record Rect(double w, double h) implements Shape {}

    static double area(Shape s) {
        return switch (s) {                                         // 21: pattern switch
            case Circle c -> Math.PI * c.r() * c.r();
            case Square(double side) -> side * side;                // 21: record pattern
            case Rect(double w, double h) -> w * h;
        };
    }

    public static void main(String[] args) throws Exception {
        var shapes = new ArrayList<Shape>(List.of(                  // 10: var, 9: List.of
                new Circle(1), new Square(2), new Rect(2, 3)));

        String report = """
                first: %s
                last:  %s
                """.formatted(shapes.getFirst(), shapes.getLast()); // 15: text block, 21: sequenced
        System.out.print(report);

        shapes.stream()                                             // 8: streams + lambdas
              .map(s -> "%s -> %.2f".formatted(s, area(s)))
              .forEach(System.out::println);

        var done = new AtomicInteger();
        try (var pool = Executors.newVirtualThreadPerTaskExecutor()) {   // 21: virtual threads
            for (int i = 0; i < 10_000; i++) {
                pool.submit(() -> { Thread.sleep(100); return done.incrementAndGet(); });
            }
        }
        System.out.println("virtual-thread tasks completed: " + done.get());
    }
}
```

1. `java Modern.java`. 10,000 tasks that each sleep 100 ms all finish in roughly the time of one
   sleep plus overhead (well under the 1,000 seconds a single thread would need, and far faster
   than 200 pooled threads), because each task gets its own virtual thread.
2. `javac --release 17 -d out Modern.java`: the errors name the 21 features
   ("patterns in switch statements are not supported in -source 17").
3. `javac --release 11 -d out Modern.java`: now records, sealed types and switch expressions fail
   too. You have just dated each line of code.
4. Stretch: add `record Triangle(double b, double h) implements Shape {}` to the `permits` list and
   recompile on 21. The switch becomes a compile error until you handle it.

## Gotchas

- **Preview ≠ released.** String templates were withdrawn after two previews. In interviews, say
  "preview in 25" for structured concurrency.
- **`List.of`/`Map.of` are immutable and reject `null`**; `Collectors.toList()` makes no
  mutability promise; `Stream.toList()` is unmodifiable.
- **`var` is not dynamic typing**, and `var list = new ArrayList<>()` infers `ArrayList<Object>`.
- **Records are shallowly immutable.** A `List` component can still be mutated; copy it with
  `List.copyOf` in the compact constructor.
- **`javax` → `jakarta` is not a JDK change.** It came from Jakarta EE 9 and arrived with Spring
  Boot 3 (which also requires Java 17).
- **Virtual threads on 21 pin inside `synchronized`** during blocking I/O; that is fixed in 24+.
  On 21, prefer `ReentrantLock` around blocking calls in hot paths.

## In interviews

Asked as "What are the main changes since Java 8?", "Why records/sealed classes?", "What are
virtual threads and when wouldn't you use them?", "Why did you (or would you) upgrade from 11 to
17/21?". Related bank questions:

- [HashMap internals and complexity](#/q/hashmap-internals): Java 8's tree bins.
- [String Immutability and String Storage](#/q/java-string-immutability): compact strings (9).
- [Process vs thread, shared variables and race conditions](#/q/process-vs-thread): a lead-in to
  virtual threads.

Follow-ups and strong answers:

- *Why upgrade an LTS?* Concrete wins: performance and GC improvements for free, virtual threads,
  records/patterns for safer code, security patches, and framework baselines (Spring Boot 3+
  needs 17). Mention the real migration costs: removed EE modules (11), encapsulated internals
  (17).
- *Do virtual threads make code faster?* No: they increase *concurrency* for blocking I/O; CPU-bound
  work gains nothing.

## Explain it in 2 minutes

Prompt: "Summarise how Java changed from 8 to 25 and why."

- 8: lambdas, streams, `Optional`, `java.time`, default methods (behaviour as data).
- 9–11: modules and encapsulation, `var`, collection factories, `HttpClient`, G1 default; EE
  modules removed.
- 12–17: records, switch expressions, text blocks, `instanceof` patterns, sealed classes, helpful
  NPEs; internals strongly encapsulated.
- 21: virtual threads, pattern matching for switch with record patterns, sequenced collections,
  generational ZGC.
- 22–25: FFM API, unnamed `_`, gatherers, no `synchronized` pinning (24); 25 finalises scoped
  values, compact source files, flexible constructors, module imports, compact headers;
  structured concurrency is still preview.

## Check yourself

1. Why were default methods necessary for Java 8's streams?
2. What makes a `switch` over a sealed interface "exhaustive", and why is that valuable?
3. Name the typical break when moving 8 → 11, and when moving 11 → 17.
4. Is structured concurrency a final feature in Java 25?
5. What problem do virtual threads solve, and what problem don't they?

### Answers

1. To add methods like `stream()` to `Collection` without breaking every existing implementation.
2. The compiler knows every permitted subtype; if all are handled, no `default` is needed, and
   adding a subtype turns unhandled switches into compile errors.
3. 8 → 11: removed Java EE/CORBA modules (JAXB etc.). 11 → 17: strong encapsulation of JDK
   internals breaking reflective access.
4. No, it is still a preview feature (fifth preview) in 25.
5. They make blocking, thread-per-task code scale to huge concurrency cheaply. They do not speed up
   CPU-bound work.
