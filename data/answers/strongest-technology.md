**Short answer:** Name one main area, not a list: for a backend engineer, "Java with Spring Boot for building backend services", and add one or two supporting skills (for example SQL and PostgreSQL, REST APIs, messaging). Back it with evidence: how long you have used it, what you built, and one deeper thing you understand. Pick something you are happy to be questioned on, because the next technical questions will go straight there.

## What they are checking

- **Self-awareness:** you know your real strengths.
- **Depth:** you can go beyond "I've used it" when they probe.
- **Fit:** your strength matches the role (Entain India's Java roles centre on Java and Spring backend work).
- **Steering:** a good answer guides the rest of the interview onto ground you know well.

## Structure

1. **The one main area**, in one sentence.
2. **Evidence:** years, what you built, scale or outcome.
3. **Depth marker:** one internal or advanced topic you understand (e.g. how Spring auto-configuration or `@Transactional` proxies work, JVM garbage collection, query tuning with `EXPLAIN`).
4. **Supporting skills**, one line.
5. **What you are improving next** (optional, shows growth).

## Template

> "My strongest area is **[Java and Spring Boot for backend services]**. I've used it for about **[5.5]** years, mainly building **[REST microservices / APIs for X domain]**.
>
> For example, I **[concrete thing, e.g. designed and built the X service that handles N requests a day / migrated Y from Z to Spring Boot 3]**.
>
> Beyond the basics, I'm comfortable with **[depth marker, e.g. how @Transactional works through proxies and its pitfalls, JPA performance like N+1 queries, thread pools and CompletableFuture]**.
>
> Alongside that I'm strong in **[supporting skill, e.g. SQL and PostgreSQL query tuning / Kafka]**, and right now I'm deepening **[growth area, e.g. system design for high-traffic systems]**."

**Before the interview**, revise the depth marker you name: the interviewer will very likely ask about it next.

## Mistakes to avoid

- Listing ten technologies; it sounds like none is strong.
- Naming something you used once, or that is on your CV but you can't defend.
- Rating yourself "10/10" in anything; "strong, still learning X" is safer and more believable.
- Naming a framework without the language underneath (Spring without core Java depth).
- No example of what you built with it.
